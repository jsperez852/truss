# RFC 0003 — Truss 0.6: economy, save, phases in the debugger

| | |
|---|---|
| Status | **Implemented** in Truss 0.6.0 |
| Date | 2026-11-08 |
| Target | Truss 0.6.0 (Godot 4.5+) |
| Evidence | Five pilot migrations of real projects (Pong, a Flappy-style game, a platformer, an idle tycoon, a 9,900-line action roguelite), each with a before/after characterization check |

## 1. Summary

The 0.5 pilots wrote the same three things by hand, and one piece of 0.5.1 was invisible in the tools:

| # | Piece | Evidence |
|---|---|---|
| A | `TrWallet`: balances with spending that returns `TrResult` | The idle pilot wrote its own `Wallet` (balance, can_afford, try_spend, earn) |
| B | `TrCurve`: a value per level, as a Resource | The idle game's upgrade formula (`ceil(x · 1.3)` per level, ×3 every 25) doesn't fit `TrStat` |
| C | `TrSave`: one Dictionary per file, safely | Two pilots wrote a score store with no error handling; none had versions or backups |
| D | `TrPhases` in the debugger tab | Level 1 games never call `Truss.boot()`, so nothing reached the tab |
| E | Fix: bus deduplication per source | The roguelite subscribes one shared effect Resource per character; 0.5.1 dropped all but the first |

## 2. Design

### A. TrWallet

Currencies are `StringName`s with `&"coins"` as default, because most games have one currency and some have two
or three. Spending is a single call that checks and subtracts (`try_spend`) so a UI can't show "affordable" and
then fail, and `try_spend_all` pays a multi-currency price all or nothing. Balances are floats: idle numbers beyond
2^53 need a big-number type, out of scope. The wallet emits a `changed` signal instead of publishing on a bus, so
it works at level 1 and 2 without a container; games that want an event connect the signal to their bus.

### B. TrCurve

A Resource with `growth` (exponential, linear, table), `rounding`, milestones and limits. The key decision is
`round_each_level`: hand-written idle formulas round at every level and grow from the rounded value, which is not
the closed form (42 vs 59 at level 10 for `3 · 1.3^level` rounded up). Both are supported, and a test checks the
per-level form against the idle game's loop for 75 levels. `total` and `max_affordable` cover "buy ×10" and
"buy max". Big-number support and arbitrary expressions are out of scope.

### C. TrSave

One file, one Dictionary, `FileAccess.store_var` without objects (no code execution through a save file).
Atomic write: temporary file, previous save kept as `.bak`, rename. Reading a damaged file falls back to the
backup. A version number and `add_migration(from, callable)` upgrade old files one version at a time; a file from a
newer build is refused, not overwritten. Optional encryption with a password. Not included: slots (use one
`TrSave` per slot path), cloud sync, auto-save timers, saving node trees.

### D. TrPhases in the debugger

`TrPhases.new(name)` sends `truss:phase [name, previous, current, frame]` when `EngineDebugger.is_active()`. The
panel logs it and keeps a "Phases" section with the current phase of each machine. This does not need the
reporter that `Truss.boot()` attaches, so it works at every level.

### E. Bus fix

`subscribe()` treats (handler, source) as the identity of a subscription. `unsubscribe(type, handler, source)`
removes one source; without `source` it removes all of the handler's subscriptions, as before.

## 3. Compatibility

Additive except E, which changes behavior only for code that subscribed the same handler with different sources
and relied on the second call being ignored, which no pilot did.
